Como construir um RAG 100% Serverless

Por Marcelo Gonçalves Última atualização em 08 Nov, 2025 Leitura de 8 min
[ADSENSE LEADERBOARD - 728x90]

Nos últimos meses, o termo Retrieval-Augmented Generation (RAG) dominou as discussões sobre LLMs. A ideia é simples, mas poderosa: em vez de depender apenas do conhecimento pré-treinado (e estático) de um modelo, nós o "alimentamos" com informações relevantes em tempo real para responder a uma pergunta.

Neste tutorial, vamos fugir da teoria. Vamos construir um sistema RAG 100% serverless na AWS. Nosso objetivo: criar uma API que permita "conversar" com um documento PDF que faremos o upload.

O que vamos construir?

Nossa arquitetura será composta pelos seguintes serviços da AWS, todos alinhados com nossa meta de ser 100% serverless:

  • S3: Para armazenar o PDF original e acionar o pipeline.
  • Lambda: Para orquestrar o processo de "chunking" (quebra do texto) e para lidar com as queries da API.
  • DynamoDB: Para armazenar os *embeddings* (vetores) dos nossos chunks de texto.
  • API Gateway: Para expor nossa função Lambda como uma API HTTP.
  • Terraform: Para gerenciar toda essa infraestrutura como código (IaC).
[ADSENSE IN-ARTICLE - 300x250]

Passo 1: A Função Lambda de "Chunking"

Primeiro, precisamos de uma função que seja acionada sempre que um novo PDF for carregado no S3. Essa função lerá o texto, o quebrará em pedaços (chunks) de tamanho gerenciável e gerará os *embeddings* (representações numéricas) de cada pedaço usando a API da OpenAI.

"O 'chunking' é talvez a parte mais crítica de um RAG. Chunks muito grandes diluem a informação; chunks muito pequenos perdem o contexto."

Exemplo de Código (Python)

Este seria um trecho da nossa função Lambda para gerar embeddings:

import boto3
import openai

def get_embedding(text, model="text-embedding-ada-002"):
    # Chama a API da OpenAI para obter o vetor
    response = openai.Embedding.create(
        input=text,
        model=model
    )
    return response['data'][0]['embedding']

Passo 2: A API de Query

Agora, criamos uma segunda Lambda, exposta pelo API Gateway. Quando um usuário envia uma pergunta, esta função irá gerar o embedding da pergunta, consultar o DynamoDB para encontrar os chunks mais próximos e, finalmente, montar um prompt para o GPT-4 responder com o contexto.
