## 2. Decisões Técnicas Críticas

### 2.1 AWS Profile Local
**`claude-dev`** para TODA operação AWS local.

### 2.2 DynamoDB: Booleanos como Números
`e_popular` e `e_projeto` são `Number (0/1)` — DynamoDB não suporta Boolean como chave de GSI.

### 2.3 Next.js: Params como Promise
`await params` ANTES de desestruturar em qualquer `page.tsx`.

### 2.4 Sharp.js: Build Especial para Lambda Linux
`backend/build.js` usa `npm install --os=linux --cpu=x64`. **NÃO alterar.**

### 2.5 OpenNext v3: Caminho de Output
ZIP do Next.js: `frontend/.open-next/server-functions/default/` (**PLURAL** `server-functions`, não singular).  
O `index.mjs` deve estar na raiz do ZIP.

### 2.6 NEXT_PUBLIC_API_URL: Runtime, Não Build
- Valor real: injetado via Lambda env var pelo Terraform
- No build CI: placeholder `https://build-placeholder.local`
- `lib/api.ts`: validação dentro de `getApiUrl()` (não em module load)

### 2.7 Admin: Build APÓS Terraform Apply
Vue.js usa `VITE_*` vars baked no build — pipeline builda admin APÓS terraform apply.

### 2.8 Logging Estruturado
Todas as 9 Lambdas emitem JSON via `backend/src/common/logger.ts`.  
`LOG_LEVEL`: `DEBUG` (dev), `INFO` (prod).

### 2.9 Terraform Remote State
Backend S3 configurado em `providers.tf`. Requer bootstrap manual.  
`infra/backend.hcl.example` → copiar para `infra/backend.hcl`.

### 2.10 PostSchedulerLambda — ConditionExpression Anti-Race
`ConditionExpression: "#status = :programado"` evita double-publish se dois schedulers rodarem simultaneamente.

### 2.11 CloudWatch Log Groups — Ordem de Criação
`depends_on = [aws_cloudwatch_log_group.*]` em cada Lambda garante que o grupo existe ANTES da Lambda ser criada, evitando auto-create sem política de retenção.

### 2.12 CORS Admin — ADMIN_ORIGIN via Terraform
Lambdas admin (`adminPosts`, `adminAuthors`, `mediaUpload`, `adminCategorias`) recebem `ADMIN_ORIGIN = "https://${module.admin.cloudfront_url}"`.  
Fallback `*` para dev local (quando env var não está setada).

### 2.13 Lambda Function URL — OAC + AWS_IAM
`authorization_type = "AWS_IAM"` + `aws_cloudfront_origin_access_control` tipo `lambda` no CloudFront.  
`aws_lambda_permission` restrito a `principal = "cloudfront.amazonaws.com"` com `source_arn = cloudfront_distribution.arn`.  
**Ninguém pode invocar a Lambda diretamente** — apenas via CloudFront.

### 2.14 HTML Sanitization — sanitize-html
`backend/src/common/sanitizer.ts` aplicado em `savePost()` antes de persistir no DynamoDB.  
Bundled pelo esbuild (sem instalação separada no ZIP).  
`sanitize-html` não é `external` no build — fica embutido no `adminPosts.zip`.

### 2.15 adminCategorias — Reutiliza admin-lambda-role
`categorias_table_arn` adicionado ao `admin-lambda-policy` (least privilege: CRUD apenas na tabela categorias).

### 2.19 Pagination Limit Parametrizado (Sessão 4)
Frontend passa `?limit=N` para cada endpoint. Backend Lambdas aceitam `limit` via queryStringParameters com fallback seguro.
- Home/recentes: limit=6 (grid 3x2)
- Artigos/Categorias/Busca: limit=9 (grid 3x3)
- Projeto/timeline: limit=8
- `getRecentPosts()` e demais funções em `frontend/lib/api.ts` aceitam parâmetro `limit`.

### 2.16 categoriasApi no EditorView — Fallback Silencioso
Se a API falhar, o dropdown usa 6 categorias hardcoded.  
Seed inicial do DynamoDB via `POST /admin/categorias` necessário após primeiro deploy.

### 2.17 FontAwesome — NPM, Não CDN
`import "@fortawesome/fontawesome-free/css/all.min.css"` em `layout.tsx`.  
`next.config.ts` tem `optimizePackageImports: ['@fortawesome/fontawesome-free']`.

### 2.18 Testes Backend (Jest)
- Config: `backend/jest.config.js` com `ts-jest` + `backend/tsconfig.test.json`
- Mock padrão: `jest.mock('../../common/dynamodb', () => ({ dynamo: { send: jest.fn() } }))`
- 47 testes em 4 suites: `getPost`, `getPosts`, `adminPosts`, `postScheduler`
