## 2. Decisões Técnicas Críticas

### 2.1 AWS Profile Local
**`claude-dev`** — SEMPRE usar este perfil.

### 2.2 DynamoDB: Booleanos como Números
`e_popular` / `e_projeto` = `Number (0/1)` — DynamoDB não suporta Boolean como chave de GSI.

### 2.3 Next.js 16: `params` é Promise
`await params` ANTES de desestruturar em qualquer `page.tsx`.

### 2.4 Sharp.js: Build Especial para Lambda Linux
`backend/build.js` usa `npm install --os=linux --cpu=x64`. **NÃO alterar.**  
No Windows: `build.js` usa `PowerShell Compress-Archive` em vez de `zip`.

### 2.5 OpenNext v3: Caminho de Output
ZIP do Next.js: `frontend/.open-next/server-functions/default/` (**PLURAL**). `index.mjs` na raiz do ZIP.

### 2.6 NEXT_PUBLIC_API_URL: Runtime, Não Build
- Build CI: placeholder `https://build-placeholder.local`
- Validação dentro de `getApiUrl()`, não em module load

### 2.7 Admin: Build APÓS Terraform Apply
Vue.js bakes `VITE_*` vars — pipeline builda admin APÓS terraform apply outputs.

### 2.8 Logging Estruturado
JSON via `backend/src/common/logger.ts`. `LOG_LEVEL=DEBUG` (dev).

### 2.9 Terraform Remote State
S3: `marcelo-goncalves-blog-dev-tfstate/blog/terraform.tfstate`  
Lock: DynamoDB `marcelo-goncalves-blog-dev-tflock` | Profile: `claude-dev`

### 2.10 PostSchedulerLambda — Anti-Race
`ConditionExpression: "#status = :programado"` evita double-publish.

### 2.11 CloudWatch Log Groups — Ordem
`depends_on = [aws_cloudwatch_log_group.*]` garante retenção antes da Lambda existir.

### 2.12 CORS Admin — ADMIN_ORIGIN
`ADMIN_ORIGIN = "https://${module.admin.cloudfront_url}"` via Terraform. Fallback `*` dev local.

### 2.13 Lambda Function URL — OAC + AWS_IAM
`authorization_type = "AWS_IAM"` + OAC SigV4. Só CloudFront pode invocar. **Ativo** ✅

### 2.14 HTML Sanitization — sanitize-html
`backend/src/common/sanitizer.ts` em `savePost()`. Bundled pelo esbuild.

### 2.15 adminCategorias — admin-lambda-role
`categorias_table_arn` no `admin-lambda-policy`.

### 2.16 categoriesApi — Fallback Silencioso
Se API falhar, EditorView usa 6 categorias hardcoded.  
**Modelo real:** `{ categoria_slug, nome, descricao? }` — NÃO usar `nome_exibicao`, `icone_fa`.

### 2.17 FontAwesome — NPM, Não CDN
`import "@fortawesome/fontawesome-free/css/all.min.css"` em `layout.tsx`.

### 2.22 Observabilidade — X-Ray + CloudWatch Alarms
- **X-Ray**: todas as Lambdas + API GW stage instrumentados. Toggle: `enable_xray_tracing` no `.tfvars`.
- **DynamoDB**: `aws-xray-sdk-core` instalado. `buildClient()` em `backend/src/common/dynamodb.ts` ativa tracing quando `XRAY_ENABLED=true`.
- **CloudWatch Alarms**: error + throttle por Lambda; 5xx + latência P99 no API GW. Toggle: `enable_cloudwatch_alarms` + `alarm_email` no `.tfvars`.
- Dev: ambos desabilitados. Prod: habilitar via `env/prod.tfvars`.

### 2.28 API_URL — Variável de Runtime (não build-time)
`frontend/lib/api.ts` usa `process.env.API_URL` (sem prefixo `NEXT_PUBLIC_`).  
**Motivo:** `NEXT_PUBLIC_*` é baked no bundle em build time pelo Next.js/SWC. A Lambda recebe a var correta em runtime, mas o código compilado já tinha o placeholder. Mudança para `API_URL` (server-only) lê do `process.env` real em runtime.  
**Lambda env var:** `API_URL = var.api_url` no `infra/modules/frontend/lambda.tf`.

### 2.29 CSS Architecture — globals.css é apenas global
`globals.css` contém **apenas**: tokens `:root`, reset, `.container`, `.highlight`, `.btn`. Tudo mais vai no CSS do componente ou da página.  
Estrutura de CSS do projeto:
- `app/globals.css` — tokens, reset, utilitários, botões cross-page (181 linhas)
- `app/home.css` — hero, `.home-layout` (grid 2-col), `.home-posts-grid`, `.home-main`, categorias, CTA, super-destaque
- `app/busca/busca.css`, `app/sobre/sobre.css`, `app/servicos/servicos.css`, `app/not-found.css` — estilos específicos de cada página
- Componentes: cada um com seu `.css` próprio importado no `.tsx`

### 2.30 Pipeline de Imagens — Arquitetura Correta
- **Upload**: arquivo original → `uploads-raw` bucket (root, sem prefixo)
- **imageProcessor**: lê de `uploads-raw`, grava variantes em `assets` bucket sob `media/` prefix  
  Ex: `assets/media/uuid-480.avif`, `assets/media/uuid-1280.webp`
- **CloudFront**: `media/*` → `S3-Assets` (assets bucket) ✅
- **CD pipeline**: `--exclude "media/*"` no `aws s3 sync` para preservar variantes entre deploys
- **Arquivos existentes**: 31 originais processados manualmente → 186 variantes em `assets/media/`

### 2.31 ResponsiveImage — Sempre BasePath
`frontend/components/ui/ResponsiveImage.tsx` **sempre** strip extensão antes de usar como basePath.  
URLs do admin antigo chegam com `.webp` appended (ex: `media/uuid.webp`). Strip → `media/uuid` → `<picture>` constrói variantes corretas (`media/uuid-480.avif` etc.).  
**Nunca** usar `<Image>` Next.js diretamente para imagens de conteúdo — sempre `<ResponsiveImage>`.

### 2.26 Pipeline de Imagens Responsiva — Mobile-First
- **imageProcessor Lambda**: gera 6 variantes por upload em paralelo (`Promise.all`):
  - `{basename}-480.avif`, `{basename}-480.webp` (mobile)
  - `{basename}-768.avif`, `{basename}-768.webp` (tablet)
  - `{basename}-1280.avif`, `{basename}-1280.webp` (desktop)
  - AVIF quality 65 (effort 2), WebP quality 80
- **mediaUpload Lambda**: retorna `basePath` sem extensão. Normaliza extensão para minúsculas antes de gravar no S3 (`foto.JPG` → `foto.jpg`).
- **S3 triggers**: `.jpg`, `.jpeg`, `.png`, `.webp`, `.heic`, `.heif` — todos disparam a Lambda.
- **Formatos aceitos pelo admin**: PNG, JPEG, WebP, HEIC, HEIF.
- **`<ResponsiveImage>` component** (`frontend/components/ui/ResponsiveImage.tsx`): detecta URL legada (`.webp`/`.jpg`) vs basePath novo → renderiza `<Image>` Next.js ou `<picture>` nativo. Totalmente transparente para quem usa (PostCard, PostPage).
- **DynamoDB `imagem_destaque_url`**: novos posts gravam basePath completo (ex: `https://cdn.../media/ts-uuid-nome`). Posts antigos têm URL `.webp` — retrocompatível via detecção no componente.
- **CloudFront**: `PriceClass_200` — Brasil (PoP São Paulo, ~5ms vs ~130ms antes).
- **Audit completo**: `docs/image-pipeline-audit.md` — 10/12 itens feitos.
