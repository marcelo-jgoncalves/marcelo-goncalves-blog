### 🚨 PADRÕES CRÍTICOS (Lições Aprendidas — Sessão 36)

**INCREMENTAL INVESTIGATION PROTOCOL** — Lesson reapplied (originally from session 35, reinforced in session 36):
- ❌ **ERRADO:** Mudança não funciona → fazer múltiplas mudanças cegas → revert → recomeçar
- ✅ **CERTO:** Diagnose → Minimal change (um token/propriedade por vez) → Test → Reflect → Próxima mudança

**Template Incremental:**
```
ANTES: [estado atual do código] → [o que não funciona?]
DIAGNÓSTICO: [root cause identificada?]
MUDANÇA MÍNIMA: [uma propriedade/token alterado]
TESTE: [comportamento observado no browser]
APRENDIZADO: [modelo mental atualizado] → [próxima hipótese]
```

**Padrão de feedback aprendido em sessão 36:**
- **Analysis vs Action** — Análise = coleta dados; ação requer instrução explícita do usuário
- **Questions Only Answer** — Pergunta = resposta específica; sem ações adicionais ou suposições
- **Guessing NUNCA** — Nunca fazer múltiplas mudanças blindas esperando que uma funcione

#### 🐛 Fix: imagens inline das postagens não aparecem (`conteudo_html` com URL "bare")
- **Relato (separado do fix de `/sobre`):** "nem localmente nem diretamente pela url do cloudfront as imagens das postagens não estão aparecendo".
- **Diagnóstico:** capa do post (`.post-cover-frame`, via `ResponsiveImage`) OK em todos os posts testados. Os outros 10 posts não têm `<img>` no corpo (não é bug).

- **Validado:** 5 novos testes em `__tests__/postUtils.test.ts` (81/81 frontend passam). `tsc --noEmit` limpo. Playwright confirma os 3 posts renderizando a imagem inline (`naturalWidth: 612/1280/1024`, `failed: none`).

### 2.67 Cache-Control immutable para arquivos public/ — Problema Conhecido (Sessão 23)
O `cd.yml` aplica `Cache-Control: public, max-age=31536000, immutable` para **todos** os assets Next.js via S3 sync. Isso é correto para `_next/static/chunks/*.js` (content-hashed) mas errado para arquivos de `public/` (ex: `foto-perfil-oculos.png`) cujo nome não muda entre versões.  
**Efeito:** browser que baixou versão antiga serve do cache por 1 ano, ignorando invalidações CloudFront.  
**Workaround imediato:** Ctrl+Shift+R (hard-refresh) ou incógnito.  
**Fix pendente (backlog #20):** separar o S3 sync em dois passos — `_next/static/**` com `immutable`, demais arquivos (public/) com `max-age=86400` sem `immutable`.
