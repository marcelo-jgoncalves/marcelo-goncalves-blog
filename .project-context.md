## 2. Decisões Tomadas

### 2.1 DynamoDB: Booleanos como Números
`e_popular` e `e_projeto` são `Number (0 ou 1)` porque DynamoDB não suporta Boolean como chave de GSI. Todos os GSIs que usam esses campos esperam `ExpressionAttributeValues: { ":val": 1 }`.

### 2.2 Next.js: Params como Promise (Breaking Change v15+)
Em `page.tsx` com `params`, usar `await params` antes de desestruturar. Já implementado em todos os arquivos. Ver: `frontend/app/post/[slug]/page.tsx:47`.

### 2.3 Sharp.js: Build Especial para Lambda Linux
`backend/build.js` instala sharp com flags `--os=linux --cpu=x64` para compatibilidade com Lambda. **NÃO alterar essa lógica.**

### 2.4 CloudFront: Host Header Não Repassado para Lambda
O CloudFront NÃO repassa o header `Host` para a Lambda SSR (causaria erro 403). O `forwarded_values.headers` só inclui `"Authorization"`. Correção aplicada em `frontend/cloudfront.tf`.

### 2.5 ZIP do Next.js: Diretório Correto
O ZIP do OpenNext deve ser criado de dentro da pasta `.open-next/server-function/default`, com `index.mjs` na raiz do ZIP. Implementado no `cd.yml`.

### 2.6 Tiptap: Version Pin no Admin
Admin usa Tiptap `^2.11.0`. O Tiptap 3.x tem breaking changes. Manter pin enquanto não houver plano de migração.

### 2.7 ImageProcessor: Destino É o Bucket de Assets do Frontend
A Lambda escreve em `DESTINATION_BUCKET` (bucket de assets do frontend), na pasta `media/`. O CloudFront do frontend tem regra `media/*` apontando para o S3 de assets.

### 2.8 Cognito: Login via Amplify SDK (Não Hosted UI)
Implementação atual usa `aws-amplify/auth` com `signIn()` direto. O Hosted UI não está configurado. Funcional mas diferente do blueprint.

### 2.9 Pipeline de Conteúdo: Injection Markers
`postUtils.tsx` injeta `<div id="inject-service-placeholder">` e `<div id="inject-ads-placeholder">` no HTML. O `page.tsx` faz `split()` por esses markers e substitui por componentes React.

### 2.10 NEXT_PUBLIC_API_URL: Runtime, Não Build
`NEXT_PUBLIC_API_URL` é injetado via Lambda env var pelo Terraform em runtime. O build usa placeholder. A validação foi movida para dentro de `getApiUrl()` (chamada por request), não no module load. **NÃO reverter para module-level throw.**

### 2.11 Admin: Build APÓS Terraform Apply
O admin Vue.js usa `VITE_*` vars baked no build. O pipeline (`cd.yml`) builda o admin DEPOIS do `terraform apply` para usar os outputs reais (API URL, Cognito IDs).

### 2.12 AWS CLI Profile Local
Perfil: **`claude-dev`** (não `devops-blog-dev`). Usar em qualquer operação AWS local.

## 3. Padrões Adotados

### TypeScript/Backend
- Usar `APIGatewayProxyHandler` como tipo do handler (não `any`)
- Importar `dynamo` de `common/dynamodb.ts` (não criar novo client)
- Importar `logger` de `common/logger.ts` (não usar `console.log`)
- Headers CORS em TODAS as respostas, incluindo errors
- Variáveis de ambiente via `process.env.TABLE_NAME`

### Logging Estruturado (logger.ts)
```json
{ "timestamp": "...", "level": "INFO", "message": "post_fetched", "requestId": "...", "slug": "..." }
```
- `LOG_LEVEL` controlado por variável Terraform (DEBUG=dev, INFO=prod)
- Errors vão para stderr, info/debug para stdout

### Frontend (Next.js)
- CSS Puro (sem Tailwind). Tudo em `globals.css`
- `revalidate = 60` como padrão ISR em pages de conteúdo
- Fontes via `next/font/google` (Inter + Space Grotesk)
- `params` sempre com `await` antes de desestruturar
- Cores via variáveis CSS: `--aws-dark`, `--aws-orange`, `--blue-600`
- Todas as páginas com ISR que chamam API devem ter `.catch()` fallback

### Terraform
- Naming: `${var.project_name}-${var.environment}-[recurso]`
- Tags padrão: `Project`, `Environment`, `ManagedBy = "Terraform"` via `default_tags`
- Profile local: `claude-dev`
- `PAY_PER_REQUEST` em todos os DynamoDB (serverless)
- State remoto: S3 + DynamoDB (backend configurado em `providers.tf`, bootstrap via `scripts/bootstrap-state.sh`)

## 5. Fluxos Principais

### Deploy (cd.yml)
```
Push main/develop
  ↓
Job 1: Build backend (npm run build → ZIPs em infra/builds/)
       Build frontend (npx open-next build → ZIP nextjs.zip)
  ↓
Job 2a (develop): terraform apply dev → S3 sync → CF invalidation
Job 2b (main):    terraform plan prod
  ↓ (main apenas)
Job 3: Aprovação manual (GitHub Environment: production)
  ↓
Job 4: terraform apply prod → S3 sync → CF invalidation
```

**Nota:** Admin é buildado DENTRO do job de deploy (após terraform outputs).

### Publicar um Post
1. Admin: Editor Vue → `POST /admin/posts` (bodyJSON) → `adminPosts Lambda` → DynamoDB `PutItem`
2. Usuário acessa `/post/[slug]` → CloudFront → Lambda SSR → `GET /post/{slug}` → `getPost Lambda` → DynamoDB `GetItem`
3. SSR processa HTML (Shiki + TOC injection) → renderiza página

### Upload de Imagem
1. Admin: `UploadModal.vue` → `POST /admin/media/upload-url` → `mediaUpload Lambda` → Presigned URL S3
2. Upload direto para S3 `uploads-raw` bucket via presigned URL
3. S3 dispara evento → `imageProcessor Lambda` → Sharp resize 1280px → WebP → salva em `assets bucket/media/`
4. CloudFront serve `/media/[filename].webp`

### Autenticação Admin
1. Vue app → `signIn()` via Amplify → Cognito → JWT token
2. Token armazenado em Amplify session
3. `api.ts:apiCall()` extrai token via `fetchAuthSession()` e inclui em `Authorization: Bearer [token]`
4. API Gateway verifica JWT via `CognitoAuthorizer` antes de invocar Lambda admin
