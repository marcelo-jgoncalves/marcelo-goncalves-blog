## 2. Decisões Técnicas Críticas

### 2.1 AWS Profile Local
**`claude-dev`** para TODA operação AWS local.

### 2.2 DynamoDB: Booleanos como Números
`e_popular` e `e_projeto` são `Number (0/1)` — DynamoDB não suporta Boolean como chave de GSI.

### 2.3 Next.js: Params como Promise
`await params` ANTES de desestruturar em qualquer `page.tsx`.

### 2.4 Sharp.js: Build Especial para Lambda Linux
`backend/build.js` usa `npm install --os=linux --cpu=x64`. **NÃO alterar.**

### 2.5 OpenNext v3: Caminho de Output
ZIP do Next.js: `frontend/.open-next/server-functions/default/` (**PLURAL** `server-functions`).

### 2.6 NEXT_PUBLIC_API_URL: Runtime, Não Build
- Valor real: injetado via Lambda env var pelo Terraform
- No build CI: placeholder `https://build-placeholder.local`
- `lib/api.ts`: validação dentro de `getApiUrl()` (não em module load)

### 2.7 Admin: Build APÓS Terraform Apply
Vue.js usa `VITE_*` vars baked no build — pipeline builda admin APÓS terraform apply.

### 2.8 Logging Estruturado
Todas as 9 Lambdas emitem JSON via `backend/src/common/logger.ts`.  
`LOG_LEVEL`: `DEBUG` (dev), `INFO` (prod).

### 2.9 Terraform Remote State
Backend S3: `marcelo-goncalves-blog-dev-tfstate/blog/terraform.tfstate`  
Lock: DynamoDB `marcelo-goncalves-blog-dev-tflock`  
Profile local: `claude-dev` (declarado em `infra/backend.hcl`).

### 2.10 PostSchedulerLambda — ConditionExpression Anti-Race
`ConditionExpression: "#status = :programado"` evita double-publish.

### 2.11 CloudWatch Log Groups — Ordem de Criação
`depends_on = [aws_cloudwatch_log_group.*]` garante grupo criado antes da Lambda.

### 2.12 CORS Admin — ADMIN_ORIGIN via Terraform
Lambdas admin recebem `ADMIN_ORIGIN = "https://${module.admin.cloudfront_url}"`. Fallback `*` para dev local.

### 2.13 Lambda Function URL — OAC + AWS_IAM
`authorization_type = "AWS_IAM"` + OAC `lambda_oac` (SigV4).  
**Na AWS atual:** ainda `NONE` (será corrigido pelo `terraform apply`).

### 2.14 HTML Sanitization — sanitize-html
`backend/src/common/sanitizer.ts` aplicado em `savePost()` antes de persistir.

### 2.15 adminCategorias — Reutiliza admin-lambda-role
`categorias_table_arn` adicionado ao `admin-lambda-policy`.

### 2.16 categoriesApi no EditorView — Fallback Silencioso
Se API falhar, usa 6 categorias hardcoded. Seed via `POST /admin/categorias` após deploy.

### 2.17 FontAwesome — NPM, Não CDN
`import "@fortawesome/fontawesome-free/css/all.min.css"` em `layout.tsx`.

### 2.18 Testes Backend (Jest)
- Config: `backend/jest.config.js` com `ts-jest`
- 47 testes em 4 suites: `getPost`, `getPosts`, `adminPosts`, `postScheduler`
- Rodar: `cd backend && npm test`

### 2.19 Pagination Limit Parametrizado (Sessão 4)
Todos os endpoints públicos aceitam `?limit=N`:
- Home/recentes: default 6 | Artigos/Categoria/Busca: default 9 | Projeto: default 8
