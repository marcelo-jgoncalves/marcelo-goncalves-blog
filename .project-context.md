## 2. Decisões Tomadas

### 2.1 DynamoDB: Booleanos como Números
`e_popular` e `e_projeto` são armazenados como `Number (0 ou 1)` porque DynamoDB não suporta Boolean como chave de GSI. Todos os GSIs que usam esses campos esperam `ExpressionAttributeValues: { ":val": 1 }`.

### 2.2 Next.js: Params como Promise (Breaking Change v15+)
Em `page.tsx` com `params`, usar `await params` antes de desestruturar. Já implementado em todos os arquivos. Ver: `frontend/app/post/[slug]/page.tsx:47`.

### 2.3 Sharp.js: Build Especial para Lambda Linux
`backend/build.js` instala sharp com flags `--os=linux --cpu=x64` para compatibilidade com Lambda. **NÃO alterar essa lógica.**

### 2.4 CloudFront: Host Header Não Repassado para Lambda
O CloudFront NÃO repassa o header `Host` para a Lambda SSR (causaria erro 403). O `forwarded_values.headers` só inclui `"Authorization"`. Correção aplicada em `frontend/cloudfront.tf`.

### 2.5 ZIP do Next.js: Diretório Correto
O ZIP do OpenNext deve ser criado de dentro da pasta `.open-next/server-function/default`, com `index.mjs` na raiz do ZIP. Detalhado em `tec.md` seção 3.

### 2.6 Tiptap: Version Pin no Admin
Admin usa Tiptap `^2.11.0`. O Tiptap 3.x tem breaking changes. Manter pin enquanto não houver plano de migração. O root `package.json` tem `^3.14.0` por engano — é lixo.

### 2.7 ImageProcessor: Destino É o Bucket de Assets do Frontend
A Lambda escreve em `DESTINATION_BUCKET` (o bucket de assets do frontend), na pasta `media/`. O CloudFront do frontend tem regra `media/*` apontando para o S3 de assets. O caminho final é `media/[timestamp]-[random]-[nome].webp`.

### 2.8 Cognito: Login via Amplify SDK (Não Hosted UI)
Apesar do blueprint mencionar Hosted UI, a implementação atual usa `aws-amplify/auth` com `signIn()` direto via SRP/Password auth. O Hosted UI não está configurado (sem `callbackUrls`/`logoutUrls` no Terraform). Isso está funcional mas é diferente do blueprint.

### 2.9 Pipeline de Conteúdo: Injection Markers
`postUtils.tsx` injeta `<div id="inject-service-placeholder">` e `<div id="inject-ads-placeholder">` no HTML após o 3º e no meio do conteúdo. O `page.tsx` faz `split()` por esses markers e substitui por componentes React reais. Abordagem necessária pois JSX não pode estar dentro de strings HTML.

## 3. Padrões Adotados

### TypeScript/Backend
- Usar `APIGatewayProxyHandler` como tipo do handler (não `any`)
- Importar `dynamo` de `common/dynamodb.ts` (não criar novo client)
- Headers CORS em TODAS as respostas, incluindo errors
- Variáveis de ambiente via `process.env.TABLE_NAME`

### Frontend (Next.js)
- CSS Puro (sem Tailwind). Tudo em `globals.css`
- `revalidate = 60` como padrão ISR em pages de conteúdo
- Fontes via `next/font/google` (Inter + Space Grotesk)
- `params` sempre com `await` antes de desestruturar
- Cores via variáveis CSS: `--aws-dark`, `--aws-orange`, `--blue-600`

### Terraform
- Naming: `${var.project_name}-${var.environment}-[recurso]`
- Tags padrão: `Project`, `Environment`, `ManagedBy = "Terraform"` via `default_tags`
- Profiles: `devops-blog-dev` (local, não hardcoded em prod)
- `PAY_PER_REQUEST` em todos os DynamoDB (serverless)

## 4. Convenções

### Nomenclatura
- Slugs: kebab-case, sem acentos, sem caracteres especiais
- DynamoDB table keys: português (ex: `autor_id`, `categoria_slug`)
- Lambda handlers: sempre `index.handler`
- Terraform resources: snake_case

### API Versioning
- URL base: `/v1/` (stage name no API Gateway)
- Pública: `/v1/post/{slug}`, `/v1/artigos`, `/v1/categoria/{slug}`
- Admin: `/v1/admin/posts`, `/v1/admin/post/{slug}`, `/v1/admin/autor/{id}`

### Status de Posts
- `"Publicado"` — visível no blog público
- `"Rascunho"` — só visível no admin
- `"Programado"` — publicação agendada (feature incompleta)

## 5. Fluxos Principais

### Publicar um Post
1. Admin: Editor Vue → `POST /admin/posts` (bodyJSON) → `adminPosts Lambda` → DynamoDB `PutItem`
2. Usuário acessa `/post/[slug]` → CloudFront → Lambda SSR → `GET /post/{slug}` → `getPost Lambda` → DynamoDB `GetItem`
3. SSR processa HTML (Shiki + TOC injection) → renderiza página

### Upload de Imagem
1. Admin: `UploadModal.vue` → `POST /admin/media/upload-url` → `mediaUpload Lambda` → Presigned URL S3
2. Upload direto para S3 `uploads-raw` bucket via presigned URL
3. S3 dispara evento → `imageProcessor Lambda` → Sharp resize 1280px → WebP → salva em `assets bucket/media/`
4. CloudFront serve `/media/[filename].webp`

### Autenticação Admin
1. Vue app → `signIn()` via Amplify → Cognito → JWT token
2. Token armazenado em Amplify session (localStorage)
3. `api.ts:apiCall()` extrai token via `fetchAuthSession()` e inclui em `Authorization: Bearer [token]`
4. API Gateway verifica JWT via `CognitoAuthorizer` antes de invocar Lambda admin
